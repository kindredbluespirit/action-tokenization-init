## Part 2: How Real VLAs Represent Actions (~15 min)

*Loading each model, inspecting its forward() and action handling code.*

All five models below are available in leRobot v0.6.0. The key takeaway: **none of them use discrete action tokens.** The field converged on continuous representations with purpose-built action experts.

### Notebooks

| # | File | Model | Action Representation |
|---|------|-------|---------------------|
| 03 | `notebooks/part2/03_act.ipynb` | `ACTPolicy` | Continuous chunks via CVAE encoder→latent→decoder. Action = raw `(chunk_size, action_dim)` tensor. No tokenization. |
| 04 | `notebooks/part2/04_diffusion.ipynb` | `DiffusionPolicy` | Denoising from Gaussian noise. Noise scheduler, timestep embedding, `generate_actions()` iterative denoising loop. |
| 05 | `notebooks/part2/05_pi0.ipynb` | `PI0Policy` (`lerobot/pi0`) | Flow matching + **action expert** (Gemma 300M). `action_in_proj`/`action_out_proj` MLPs. Continuous actions via ODE integration. Has `train_expert_only` flag. |
| 06 | `notebooks/part2/06_smolvla.ipynb` | `SmolVLAPolicy` | **Cross-attention** action expert. VLM latents attend to action expert via `cross_attn`. `expert_width_multiplier=0.75`. Continuous output. |
| 07 | `notebooks/part2/07_pi05.ipynb` | `PI05Policy` | Flow matching + action expert with **adaRMS conditioning**. No FAST tokens in leRobot implementation. |

### Manim Scenes

| Scene | Content |
|-------|---------|
| s06_action_anatomy | 7-dim action vector, 3D coordinate system |
| s07_chunking | Action matrix `(H × D)` with sliding window |
| s08_act | CVAE diagram: encoder→μ,σ→sample→decoder→action |
| s09_diffusion | Noise→denoise→denoise→action animation |
| s10_pi0_family | Architecture diagram: SigLIP → PaliGemma → action expert → flow matching. Side-by-side: pi0 vs pi05 (adaRMS) vs SmolVLA (cross_attn) |

### Key Message
The predominant paradigm in production VLAs is **continuous action with an explicit action expert**. Tokenization is the exception, not the rule.

## Part 3: pi0-FAST — The Tokenization Experiment (~12 min)

*Why pi0-FAST attempted tokenization, how FAST works, and why pi0.5 reverted.*

### Notebooks

| # | File | What It Demonstrates |
|---|------|---------------------|
| 08 | `notebooks/part3/08_fast_pipeline.ipynb` | Load `lerobot/fast-action-tokenizer`. Step-by-step: normalize → DCT → quantize → flatten → BPE. Show 10× compression over naive binning. Round-trip reconstruction. |
| 09 | `notebooks/part3/09_pi0fast_inference.ipynb` | Load `lerobot/pi0fast-base`. Autoregressive action token generation. KV-caching for speed. `decode_actions_with_fast()` — inverse DCT back to continuous. Compare: no action expert (uses VLM backbone directly). |
| 10 | `notebooks/part3/10_comparison.ipynb` | Side-by-side comparison table: pi0 (flow matching, 1× train time), pi0-FAST (autoregressive tokens, 5× faster), pi0.5 (back to action expert + flow matching). Discussion of tokenization trade-offs. |

### Manim Scenes

| Scene | Content |
|-------|---------|
| s11_dct | Signal → DCT → frequency domain, energy concentration at low freqs |
| s12_bpe | Sparse DCT matrix → flatten → BPE tokens, 10× compression animation |
| s13_pi0fast | Same VLM as pi0 but action head replaced with FAST token decoder |
| s14_pi05 | pi0.5 hybrid: action expert + flow matching, no FAST in leRobot |
| s15_conclusion | Timeline: ACT → Diffusion → pi0 → pi0-FAST → pi0.5. "Tokenization promising for speed, continuous still wins for dexterity." |

### Key Message
Physical Intelligence went from flow matching (pi0) → pure autoregressive tokens (pi0-FAST, 5× faster) → back to flow matching + action expert (pi0.5). Tokenization gives training efficiency but loses the precision needed for dexterous control. The pendulum is still swinging.

### Scene Convention

Each scene file defines one or more `Slide` classes inheriting from `manim_slides.Slide`:

```python
from manim import *
from manim_slides import Slide

class TitleScene(Slide):
    def construct(self):
        title = Text("Action Tokenization for Robots")
        self.play(Write(title))
        self.next_slide()  # pause point
        self.play(title.animate.to_edge(UP))
```
